# Day41 Lesson 1 — 旅行三人小队：角色与工单（先读再答）

> 挂钩上游：**实现「旅行规划师–本地向导–预订专员」Multi-Agent 系统**  
> 承接 Day39–40：你会写 `Agent` / `Task` / `Crew` / `Process.sequential`。  
> 本课**不跑代码**；先把三人职责和三张工单顺序讲清。

## 类比：帮朋友订一个周末短途

需求很短：例如「杭州两天一夜，预算不高」。三个人按**工单顺序**干活，不是开会抢麦。

| 工位 | Agent 名（本课约定） | 干什么 | 不干什么 |
|------|----------------------|--------|----------|
| **旅行规划师** | `planner` | 根据需求定骨架：天数、节奏、主题（吃/景/闲） | 不写具体店名长清单、不假装下单 |
| **本地向导** | `guide` | 按骨架补 **2～3 个**可走的点（景点/街区/吃法），短句即可 | 不推翻整份行程、不谈价格下单 |
| **预订专员** | `booker` | 根据前两步，给出「建议订什么」的**短清单**（交通/住/票的假想项） | **不调用真实订票网站**；够清楚就收工 |

为什么拆三个？  
规划管「大方向」、向导管「本地细节」、预订管「落成可执行条目」。糊成一个人容易既空又乱。

## 和前几天对照

| | Day38 AutoGen | Day39–40 CrewAI | 今天 Day41 |
|--|---------------|-----------------|------------|
| 味道 | 三人**轮流说话** | 两人**任务流水线** | 三人 **CrewAI 流水线** |
| 骨架 | `RoundRobinGroupChat` | `Crew` + sequential | **同一个 CrewAI 骨架**，名单/工单变 3 |
| 接力 | 消息历史 | `Task.context=[上一张]` | 向导接规划师；预订接规划师+向导 |

```text
用户需求（短途）
   │
   ▼
Task1 planner  →  行程骨架
   │ context
   ▼
Task2 guide    →  本地 2～3 个点
   │ context
   ▼
Task3 booker   →  建议预订短清单
   │
   ▼
kickoff() 结束（Process.sequential）
```

## 共享什么

CrewAI 里后一张 Task 要看见前面的结果，靠 **`context=[前面的 Task]`**，不是靠 RoundRobin 聊天记录。
