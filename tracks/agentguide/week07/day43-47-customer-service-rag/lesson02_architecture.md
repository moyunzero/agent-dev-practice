# Day43–47 Lesson 2 — 架构设计（先读再画）

> 挂钩上游：**完成架构设计**  
> 依据 Lesson 1：库精确 / FAQ / 需人工。本课画出数据流，仍少写业务代码。

## 上游强制的核心路径

```text
用户问句
   │
   ▼
┌─────────────┐
│ 入口 API    │  解析：意图粗分 / 抽出订单号·SKU 等
└──────┬──────┘
       │
       ▼
  能精确查库？ ──是──► PostgreSQL（订单/商品…）──► 有行？──是──► 返回答案
       │ 否                              │ 否
       ▼                                 ▼
       └──────────────► FAQ / 文档检索（模糊） ◄──┘
                              │
                              ▼
                       够置信？──是──► 基于片段生成/摘录答案
                              │ 否
                              ▼
                       「需人工」占位（本块可不接真人坐席）
```

要点：**先库后文档**——不是「向量库包打天下」。

## 组件怎么拆（本仓偏好）

| 组件 | 职责 | 本块最小形态 |
|------|------|--------------|
| **API** | 收问句、返 JSON | FastAPI 一个 `POST /ask` |
| **路由/编排** | 决定走库还是 FAQ | 纯函数或薄服务；可先规则（有订单号→查库） |
| **PostgreSQL** | 订单/商品等事实 | 本地一库几张表 + 种子数据 |
| **FAQ 检索** | 政策/说明文档 | Chroma（或已学向量库）+ 几篇 MD/FAQ |
| **生成（可选）** | 把检索结果说成人话 | Ollama；库命中也可模板直接答 |

Day48–51 再挂：Prometheus/Grafana、LangSmith、Compose、压测。本课架构图上可画成「以后接」，不实现。

## 和「纯 Naive RAG」差在哪

| | 纯文档 RAG | 本项目（上游） |
|--|------------|----------------|
| 订单状态 | 硬从文档猜 | **SQL 精确行** |
| 退货政策 | 向量检索 | FAQ 检索 |
| 失败 | 常幻觉编造 | **明确需人工** |
