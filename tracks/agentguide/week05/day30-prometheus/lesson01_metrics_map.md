# Day30 Lesson 1 — 三类指标直觉（先读再答）

Prometheus 里最常用三种「仪表」：

| 类型 | 只增不减？ | 人话 | 典型用途 |
|------|------------|------|----------|
| **Counter** | 是（重启才清零） | 累计计数器 | 请求总数、错误总数、token 消耗、缓存命中次数 |
| **Histogram** | 观察值打进桶 | 量尺 + 分桶 | **每次请求耗时**、响应体大小 → 可算 P50/P99 |
| **Gauge** | 可升可降 | 温度计 | 当前并发连接数、队列长度、内存占用 |

## 上游「核心指标」怎么对应

| 业务说法 | 怎么从指标算出来 | 常用类型 |
|----------|------------------|----------|
| **QPS**（≈RPS） | `rate(http_requests_total[1m])`：1 分钟内请求 Counter 的增速 | Counter |
| **延迟** | Histogram 的桶 → `histogram_quantile(0.99, ...)` ≈ P99 | Histogram |
| **错误率** | `rate(错误Counter) / rate(总请求Counter)` | 两个 Counter（或带 status label 的同一 Counter） |

```text
请求进来 ──► Counter +1（总数）
             │
             ├─ 成功 / 失败 → 带 label 的 Counter（或错误单独 +1）
             │
             └─ 耗时 0.12s ──► Histogram.observe(0.12)
```

## 易混对照（抽问前必读）

| 概念 | 对 | 错 |
|------|----|----|
| Counter | 只加；用 `rate()` 看「每秒多少」 | 把当前在线人数做成 Counter |
| Histogram | 记录**每次**耗时分布 | 用 Gauge 记「最后一次延迟」当 P99 |
| Gauge | 当前水位 | 用 Gauge 当「历史总请求数」 |
