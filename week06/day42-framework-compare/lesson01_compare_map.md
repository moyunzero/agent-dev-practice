## 一句话设计哲学

| 框架 | 哲学（人话） | 本周你摸到的形态 |
|------|--------------|------------------|
| **AutoGen（AgentChat）** | 多智能体像**开会**：按规则轮流发言，靠对话推进 | `RoundRobinGroupChat`；消息历史 = 共享状态 |
| **CrewAI** | 多智能体像**剧组按工单干活**：谁 + 干什么 + 怎么排 | `Agent` / `Task` / `Crew` / `Process.sequential`；`context` 接力 |

```text
AutoGen：  任务进会议室 → A 说 → B 说 → … → 关键词/条数上限散会
CrewAI：   任务进剧组   → 工单1做完 → 工单2做完 → … → kickoff 跑完
```

上游说的「对话式 vs 层级/顺序式」：本周 AutoGen 练的是**对话式轮转**；CrewAI 练的是**顺序工单**（hierarchical 只知道要经理，没深挖）。

## 优点 / 缺点（结合本周体验，不吹不黑）

| | AutoGen（你练过的） | CrewAI（你练过的） |
|--|---------------------|---------------------|
| **优点** | 对话自然、适合「互相改稿/评审」；终止条件直观（`APPROVE` / 条数） | 职责与步骤写在 Task 上，先后依赖清楚；`context` 明确谁看见谁 |
| **缺点** | 步骤依赖弱时容易变成轮流闲聊；角色全靠 `system_message` 自律 | 不像「开会」那么灵活；漏写 `context` 下游就瞎；依赖/体积相对重 |
| **本周坑** | 小模型不一定说 APPROVE → 靠 `MaxMessageTermination` | 小模型乱编景点/店名 → 验收结构不验收攻略真假 |

> 官方还标过 AutoGen 进入 maintenance、新绿可看 Agent Framework——**选课仍学 AutoGen 现役 API**；对比时心里有数即可。

## 适用场景（怎么选）

| 更适合 AutoGen 味 | 更适合 CrewAI 味 |
|-------------------|------------------|
| 需要来回讨论、批评、改一版再评（如口号评审、代码评审对话） | 步骤固定：先调研再写再订（如旅行骨架→补点→建议预订） |
| 「谁接着说」比「第几张工单」更重要 | 「必须先做完 A 再做 B」很硬 |
| 想快速看多人对话流 | 想把流程写成可维护的任务列表 |

口诀：**爱讨论选开会（AutoGen）；爱流程选流水线（CrewAI）。**
