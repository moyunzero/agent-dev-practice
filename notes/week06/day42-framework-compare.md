# AutoGen 还是 CrewAI：用「开会 vs 流水线」做选型

多智能体框架很多，名字也很多。真正要动手时，常卡在一句话：**这两套该怎么选？**

本文只认真对比你最容易先摸到的两条路——**AutoGen（对话轮转）** 与 **CrewAI（任务流水线）**：设计哲学、优缺点、适用场景。其它框架文末只扫名，不装不跑。

## 你将会得到什么

1. 用「开会 / 流水线」说清两种哲学  
2. 各记住一条优点、一条缺点  
3. 面对业务题时，能选框架味并讲清理由  
4. 知道市场上还有哪些常见名字（仅扫名）

本文是**选型对照**，不是安装教程；不要求你再起一个新项目。

## 零基础名词表

> 建议先读完再往下看对照表。每个词：**是什么 → 在本文干什么 → 怎么区分**。

### Multi-Agent（多智能体）

| 层 | 说明 |
|----|------|
| **是什么** | 不止一个「角色」协作完成一件事，而不是单模型单轮问答 |
| **在本文干什么** | AutoGen 与 CrewAI 都是组织多个角色的架子 |
| **怎么区分** | 单 Agent + 工具 = 一个人干活；Multi-Agent = 多人怎么协作 |

### AutoGen（本文口径：AgentChat）

| 层 | 说明 |
|----|------|
| **是什么** | 偏「对话协作」的多智能体框架；本文指现役 **AgentChat** API |
| **在本文干什么** | 代表「开会」这一味：轮流发言、靠消息推进 |
| **怎么区分** | 不是 CrewAI 的工单列表；共享状态主要是**消息历史** |

### RoundRobinGroupChat（轮转群聊）

| 层 | 说明 |
|----|------|
| **是什么** | 按名单轮流发言的开会规则 |
| **在本文干什么** | AutoGen 侧你最常摸到的协作形态 |
| **怎么区分** | 轮到谁说话 ≠ 做完一张固定工单；适合互评、改稿、头脑风暴 |

### 终止条件（如关键词 / 条数上限）

| 层 | 说明 |
|----|------|
| **是什么** | 什么时候散会：例如有人说出 `APPROVE`，或消息条数到顶 |
| **在本文干什么** | 开会型协作需要明确「何时停」，否则容易闲聊到爆 |
| **怎么区分** | CrewAI 的 sequential 更像「工单列表跑完就结束」，不是靠口令散会 |

### CrewAI

| 层 | 说明 |
|----|------|
| **是什么** | 偏「角色 + 工单 + 剧组」的多智能体框架 |
| **在本文干什么** | 代表「流水线」这一味：谁做什么、按什么顺序做 |
| **怎么区分** | 核心对象是 Agent / Task / Crew / Process，不是群聊轮次 |

### Agent / Task / Crew / Process

| 层 | 说明 |
|----|------|
| **是什么** | 谁（Agent）+ 干什么（Task）+ 装进剧组（Crew）+ 怎么排活（Process） |
| **在本文干什么** | CrewAI 选型时，你应想到这四件套 |
| **怎么区分** | Agent 是人，Task 是事；不要把设定糊成一个对象 |

### `Process.sequential` 与 `context`

| 层 | 说明 |
|----|------|
| **是什么** | sequential = 按任务列表一个接一个；`context` = 下游要读哪些上游产出 |
| **在本文干什么** | 解释为何旅行规划、投研简报更像流水线 |
| **怎么区分** | 漏写 `context`，下游看不到上游结果；这和 AutoGen「全员看见聊天记录」不是一回事 |

```text
AutoGen（开会）:  进会议室 → A 说 → B 说 → … → 口令/条数散会
CrewAI（流水线）: 进剧组   → 工单1 → 工单2 → … → kickoff 跑完
```

## 设计哲学对照

| 框架 | 一句话哲学 | 共享状态更像 |
|------|------------|--------------|
| **AutoGen** | 多智能体像**开会**：按规则轮流发言，靠对话推进 | 消息历史 |
| **CrewAI** | 多智能体像**剧组按工单**：谁 + 干什么 + 怎么排 | Task 产出 + `context` 接力 |

上游常说的「对话式 vs 层级/顺序式」：AutoGen 这边先吃透**对话式轮转**；CrewAI 这边先吃透**顺序工单**（hierarchical / 经理分派知道有，不必一上来深挖）。

口诀：**爱讨论选开会（AutoGen）；爱流程选流水线（CrewAI）。**

## 优点与缺点（结合动手体验）

| | AutoGen | CrewAI |
|--|---------|--------|
| **优点** | 对话自然，适合互评、改稿、头脑风暴；终止条件直观（关键词 / 条数） | 步骤写在 Task 上，先后依赖清楚；`context` 明确谁看见谁 |
| **缺点** | 步骤依赖弱时容易轮流闲聊；角色边界主要靠 `system_message` 自律 | 不如开会灵活；漏写 `context` 下游就瞎猜；依赖与体积相对重 |

### 新手向坑（各记一个）

| 框架 | 现象 | 常见原因 | 处理思路 |
|------|------|----------|----------|
| AutoGen | 评审永远不说 `APPROVE`，会议拖很长 | 小模型不一定守口令 | 加消息条数上限等硬终止 |
| CrewAI | 下游答得像没看见上游 | 漏写或写错 `context` | 检查 Task 的 `context=[...]` 是否指向真正上游 |

## 适用场景：怎么选

| 更适合 AutoGen 味 | 更适合 CrewAI 味 |
|-------------------|------------------|
| 来回讨论、批评、改一版再评（口号评审、代码评审对话） | 步骤固定：必须先 A 再 B 再 C（旅行骨架→补点→建议预订） |
| 「谁接着说」比「第几张工单」更重要 | 「必须先做完 A 再做 B」很硬 |
| 想快速看多人对话流 | 想把流程写成可维护的任务列表 |

### 场景速判（示例）

| 场景 | 更像 | 为什么 |
|------|------|--------|
| 写口号再互相改到满意 | AutoGen | 互评、改稿，开会味 |
| 旅行：先规划再补点再建议预订 | CrewAI | 先后依赖硬，流水线味 |
| 客服质检：写稿 ↔ 挑毛病到满意 | AutoGen | 来回改，不是固定工单 |
| 投研：搜集 → 算指标 → 写摘要 | CrewAI | 顺序不能乱 |
| 头脑风暴产品名，直到有人说「就这个」 | AutoGen | 轮流发言 + 口令散会 |

没有唯一正确答案时，看**协作形态**：要讨论就开会，要工序就流水线。

## 其它框架（只扫名）

市场上还有很多多智能体架子，例如：agentUniverse、AgentScope、Qwen-Agent、Lagent、PraisonAI 等。  
**本文不装不跑。** 选型时先记住：你至少应真正摸过 **两种**——一种对话协作、一种任务流水——再决定要不要开第三套。

另：生态在演进（例如 AutoGen 相关产品线有过维护/迁移讨论）。学课与选型时，以你**实际能跑通的现役 API**为准，并对照官方当前文档。

## 收束

选框架时先问一句：**这事儿更像开会，还是更像流水线？**

- 要互评、改稿、轮流发言 → **AutoGen 味**  
- 要固定步骤、明确接力 → **CrewAI 味**

两条都摸过，再谈「第三套框架值不值得上」。
